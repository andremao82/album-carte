# Album carte Pokémon — nota di progetto

## Cos'è
App web personale in un unico file HTML (`app/index.html`, ~215 KB, HTML + CSS + JS senza librerie esterne) per catalogare ~500 carte Pokémon, quasi tutte italiane. Ispirata a Pokefolio. Uso personale, non di scambio.

- Online: **Cloudflare Pages** (dal 21/10/2026; dal passaggio a GitHub pubblicato in automatico da `main` con `.github/workflows/pubblica.yml`, wrangler sul progetto Direct Upload esistente; riserva: caricamento manuale dello zip da Workers & Pages → progetto → nuova distribuzione). Indirizzo: **https://carte-pokemon-5vf.pages.dev/** (progetto `carte-pokemon-5vf`; è anche `SITO` in `strumenti/pacchetto.sh`). Prima: https://spectacular-horse-23994f.netlify.app/ (Netlify, sospeso a crediti finiti il 21/10; da non usare più).
- Su iPhone: icona a schermo intero creata dal profilo `carte.mobileconfig` (Web Clip, etichetta "Carte Pokémon", `PayloadIdentifier: it.albumcarte.profile`, nessuna scadenza). Account sviluppatore aziendale: non va usato. In preparazione anche un'app nativa firmata con l'Apple ID personale gratuito (vedi sezione App iOS).
- Dati salvati nel browser del telefono (localStorage + IndexedDB per la coda foto).

## Repository (dal 21/10/2026 sera)
Il progetto vive in un **repository GitHub privato** e si lavora con **Claude Code**; prima viveva in una pagina Artifact ("kit") letta e ripubblicata a ogni chat del Progetto claude.ai. La pagina del kit è **archiviata**: non va più aggiornata (due fonti divergerebbero).
- `CLAUDE.md` — istruzioni per Claude Code (metodo, regole di prodotto, fine lavoro). Le istruzioni del vecchio Progetto claude.ai sono confluite lì.
- `app/` — il sito pubblicato e **sorgente unica**: `index.html` (l'app), `sw.js` (service worker, `VERSION = 'album-v3'`, rete prima e copia conservata se il sito non risponde), `manifest.webmanifest`, `_headers` (tipo corretto per il profilo), `carte.mobileconfig` (URL = SITO), icone.
- `test/` — test automatici con JSDOM (`*_test.js`), `percorsi.js` (tutti i percorsi, relativi al repository), `package.json`.
- `screenshot/` — script Puppeteer + Chromium (`shot*.js`) a 390×844; immagini in `.work/shot/`. `@sparticuz/chromium` funziona solo su Linux x64 (sessioni cloud di Claude Code, GitHub Actions); su Mac serve `CHROME_PATH` (non provato).
- `ios/` — progetto Xcode dell'app nativa SwiftUI (`CartePokemon.xcodeproj`, file Swift, icona) e `ISTRUZIONI.md` per l'utente. Dal clone del repository si apre direttamente in Xcode.
- `strumenti/` — `setup.sh` (dipendenze), `test.sh` (tutti i test, o `test.sh nome`), `estrai_js.py` (JavaScript dell'app in `.work/app.js`), `pacchetto.sh` (scrive `SITO` nel profilo e crea `.work/album-carte-pwa.zip`, solo riserva), `ios.sh` (`.work/CartePokemon-ios.zip`), `patch_modello.py` (modello per le modifiche mirate); `storico/` = patch delle chat precedenti, solo riferimento (puntano ai percorsi della vecchia sandbox `/mnt/user-data`, `/home/claude`).
- `.github/workflows/` — `verifica.yml` (test a ogni push e PR), `pubblica.yml` (test e poi pubblicazione di `app/` su Cloudflare Pages a ogni push su `main`; segreti `CLOUDFLARE_API_TOKEN` con permesso Account › Cloudflare Pages › Edit e `CLOUDFLARE_ACCOUNT_ID`).
- `.work/` — file generati, non versionati (`.gitignore`, che esclude anche i `backup-carte-*.json`).

## Metodo
1. `bash strumenti/setup.sh`, poi `bash strumenti/test.sh` (deve passare tutto prima di iniziare).
2. Leggere solo le parti di codice da toccare (grep su `.work/app.js` o su `app/index.html`).
3. Modificare con sostituzioni mirate (Edit con testo unico, o `rep()` di `patch_modello.py` che fallisce se il testo non è unico); mai riscrivere un file da zero.
4. `strumenti/test.sh`; per ogni funzione nuova un test nuovo in `test/` (percorsi da `require('./percorsi')`).
5. Screenshot se cambia l'aspetto.
6. Aggiornare questa nota (Funzioni / App iOS e Punti aperti), commit, push: la pubblicazione è automatica se i test passano. Niente più zip da consegnare né pagina del kit da ripubblicare.

## Regole
- **Lavori in parallelo**: con il kit due chat aperte insieme si cancellavano a vicenda le modifiche (successo il 18/10 con la Home). Con git il problema diventa un conflitto visibile: un ramo per lavoro, `git pull` prima di iniziare, mai `push --force` su `main`.
- Hosting: Cloudflare Pages (piano gratuito; i caricamenti non costano crediti come su Netlify, ma conviene comunque raggrupparli: un push su `main` = una pubblicazione). Il progetto `carte-pokemon-5vf` è di tipo **Direct Upload**: Cloudflare non permette di convertirlo all'integrazione Git, e un progetto nuovo avrebbe un altro indirizzo (dati da spostare col backup); per questo si pubblica con wrangler da GitHub Actions. `_headers` ha la stessa sintassi di Netlify. Netlify abbandonato il 21/10/2026 (300 crediti al mese, 15 a pubblicazione, finiti).
- **I dati stanno nel dominio**: localStorage e IndexedDB sono legati all'indirizzo del sito. Cambiando dominio il catalogo non si sposta da solo: backup dal vecchio indirizzo, ripristino sul nuovo. Il vecchio sito sospeso si apre ancora dalla copia del service worker (rete prima, copia conservata se la risposta è un errore), quindi il backup si può fare anche da lì.
- Service worker: incrementare `VERSION` se cambia la lista dei file in cache.
- L'anteprima dentro Claude mostra solo l'aspetto (catalogo vuoto, chiamate esterne bloccate).
